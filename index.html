Docs

One endpoint.
Thirty seconds to ship.

Single GET route. Params q (required), n (1–10, default 5). JSON back with titles, URLs, snippets, and which engines answered.

GET/api/search?q=…&n=5
# search from anywhere
curl "https://YOUR-DEPLOY/api/search?q=sri+lanka+news&n=5"
const r = await fetch(
  `https://YOUR-DEPLOY/api/search?` +
  new URLSearchParams({ q: query, n: '5' })
);
const { results } = await r.json();
# python
import requests
r = requests.get(
  "https://YOUR-DEPLOY/api/search",
  params={"q": query, "n": 5},
).json()
for hit in r["results"]:
    print(hit["title"], hit["url"])
# response shape
{
  "query": "sri lanka news",
  "results": [{
    "title": "…",
    "url": "https://…",
    "snippet": "…",
    "engine": "wikipedia"
  }],
  "engines": ["wikipedia"],
  "cached": false
}

Layer one

Bring your own SearXNG.
Or don't. It works either way.

One docker command on any always-on machine gives Orin Search a private, full-power engine. Set SEARXNG_URL and it becomes authoritative — the public layers stay as automatic backup.

# your own search engine in one line
docker run -d --name searxng --restart unless-stopped \
  -p 8080:8080 searxng/searxng
